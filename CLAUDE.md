# LeadScan — notas do projeto

- UI e textos em pt-BR. Tom humano (sem clichês de IA, sem tríades de adjetivos). Nunca inventar dados de empresas: campo ausente = "Não encontrado".
- Stack: Next.js 16 (App Router, `proxy.ts`, APIs de request assíncronas), Tailwind v4 + shadcn (radix-nova), Prisma 7 + PostgreSQL via `@prisma/adapter-pg`. Banco local: `npm run db:start` (Prisma Dev).
- Economia de tokens é requisito: filtros, score, templates, links e primeira versão das mensagens são código. IA só em `lib/ai/tasks.ts`, com cache em `AICache`.
- Toda mutação passa por `action()` em `lib/action.ts` e toda query filtra por `userId`.
- Mudou pesos do score? Incremente `SCORE_VERSION` em `lib/scoring/index.ts` (leads antigos são recalculados).
- Sites gerados: `SiteSpec` (`lib/templates/types.ts`) renderizado por `components/site` com container queries (`@3xl`, `@5xl`).
- Verificação: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
- Banco local (`prisma dev`/PGlite) atende UMA conexão por vez: `lib/db.ts` usa pool 1 em dev. Não rode scripts/seed/studio com o `npm run dev` ligado. Schema mudou? Gere a migração com `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script` e aplique com `prisma db execute` (o `db push` pede confirmação humana).
- Actions sem sessão (login) usam `publicAction()` (rate limit por IP). Uploads: `lib/media/store.ts` (sharp + moderação). Segredos de usuário: `lib/crypto/secrets.ts`.
- Pagamentos: só `applyPaymentUpdate()` (lib/payments/service.ts) transforma cobrança em venda — idempotente. Ranking/níveis leem `Sale` verificada (`lib/ranking`, `lib/gamification`); datas agrupadas em America/Sao_Paulo via SQL.
- Tempo real: `publish()` em `lib/realtime.ts` + `<LiveRefresh topics>` no cliente (SSE em `/api/live`).
- IA por usuário: `getAI(userId)` prefere a conexão do usuário (`lib/ai/connections.ts`), senão a da plataforma. Catálogo e links de "levar para…" em `lib/ai/catalog.ts`.
- Imagens do SiteSpec: só `https://` ou rotas internas (`INTERNAL_IMAGE_RE`: `/api/media/…`, `/api/places-photo/…`).
- Identidade visual (obrigatória em telas novas): preto `ink` #0A0D0F + branco + lima #EFFF00 (~10%, só CTAs/estado ativo/destaque), Inter, tokens em `app/globals.css`. Lima NUNCA como texto/ícone sobre fundo claro (sem contraste): use `text-brand-ink`. Botão principal = `Button` padrão (lima); escuro = `variant="ink"`; WhatsApp = `bg-whatsapp` (texto preto). Cards: `rounded-lg border bg-card shadow-soft`. Sidebar sempre escura com indicador lima. Gráficos usam `--chart-1/3` (validados), não o lima puro.
- Marca: LeadScan — vetor da logo oficial (pessoa com cabeça-rede lima, seta zigue-zague prateada, alvo lima) em `components/app-shell/logo.tsx`; ids do SVG via `useId` (nunca fixos). Solta só em fundo escuro, `boxed` no claro. Wordmark em Montserrat (`font-brand`), o resto do app é Inter. Selos/insígnias SVG em `components/profile/insignia.tsx`; `badgeKeyFor()` decide qual aparece no canto da foto (`UserAvatar badge=`).
- Busca: sem cidade = busca geral (UF inteira ou Brasil) via `lib/domain/regions.ts`; sem categoria = busca variada (`planMix` em `lib/leads/mix.ts`: sorteia categoria × estado que existem no índice da base, estados pouco usados primeiro, seed = id da busca). Empresas NOVAS primeiro (`excludeKnown()`: externalId, `dedupeKey` nome|cidade|UF, telefone em dados reais); se faltar para a quantidade pedida, a busca completa com leads que o usuário já tinha (mesma categoria/lugar, menos NOT_INTERESTED/WON) — o card mostra "Já apareceu" (lead criado antes da busca). Busca geral espalha: `regionBudget` spread ≈ limite/4 cidades (até 80), Brasil intercala estados. Mock pagina por `offset`.
- Chat: `lib/chat/service.ts` (conversa por par, bloqueio nos 2 sentidos), mídia só por `/api/chat/media/[id]` (checa membro, suporta Range). Presença = heartbeat `/api/presence` → `lastActiveAt`; `presenceOf()` (online <2min, inativo <30min). Eventos ao vivo: UMA EventSource por aba (`lib/client/live.ts`); não crie EventSource direto.
- Bundle do navegador: nada de `zod` em código cliente — use `lib/domain/filters.ts` e `lib/templates/constants.ts` (os módulos com zod são só do servidor).
- Layout mobile: grade com tabela/texto truncado precisa de `grid-cols-1` (senão a coluna automática estoura a tela); `<table className="sr-only">` estoura — envolva num `div.sr-only`.
- Ícones de presença (site/Instagram/WhatsApp/Facebook/Google/telefone) sempre clicáveis: destinos em `lib/leads/links.ts` (só http(s); DEMO: WhatsApp sem destinatário e telefone sem link), componente `PresenceIcons`. Link dentro de card clicável: `relative z-10` acima do `after:inset-0`.
- Busca aberta: `/search` sem `?s=` redireciona para a última busca aberta (`Search.openedAt`, sem `closedAt`; `openSearchId`) com a vista guardada no cookie `ls_busca` (filtros + lead, `rememberSearchView`). Abrir resultados marca `openedAt` via `after()`; só "Fechar busca" (`closeSearch`) tira da tela. `?nova=1` ou `?q=` abrem o formulário vazio.
- Listas: "remover" lead = tirar de Meus leads/Favoritos (`setLeadLists`), nunca apagar (a busca depende do registro para não repetir). Protótipo tem `favorite` (favoritos primeiro); mudar estrela não mexe no `updatedAt`.
- Gráficos "ruins" esquentam: tokens `--heat-1/2/3` (âmbar→vermelho). `TimeChart`: `tone: "bad"` (maior = pior), `heat` (abaixo da média esquenta) e `partialLast`; sempre com legenda + frase-resumo em texto. Funil esquenta etapa com perda alta.
- Miniaturas de site: passe `previewSpec(spec)` (lib/templates/preview.ts) ao `ScaledSite` — só 2 seções e fotos menores; o card só desenha perto da tela (`eager` acima da dobra).
- Celular: `touch-action: manipulation` (sem zoom de dois toques) e campos com 16px em tela de toque (iPhone não amplia ao focar). Não use `maximum-scale`.
- Vercel/serverless: `vercel-build` roda `prisma migrate deploy`; CLI usa conexão direta (DIRECT_URL/DATABASE_URL_UNPOOLED). Corpo/resposta até 4,5 MB: vídeo/áudio grande sobe em partes (`/api/chat/[id]/media/part`, Media `source="partial"` até fechar) e mídia do chat sai em fatias (substring no bytea). SSE se renova antes do `maxDuration` e o cliente recebe `resync`. Fila de buscas: `after()` + reserva QUEUED→RUNNING no banco; RUNNING parado 2 min é retomado.
- Muita gente ao mesmo tempo: placar/faturamento da comunidade em cache compartilhado (`lib/ranking/cached.ts`, tag "community", invalidada no `publish()` de eventos da comunidade). Layout do app = 1 consulta (`shellCounts`); métricas do dashboard = 1 consulta. Prefira agregados com FILTER a várias `count()`.
- Versão pública (AUTH_MODE=public; vazio = public em produção): sem demonstração; busca nunca usa `mock` (padrão OpenStreetMap, `getProvider` cai numa fonte real); contas `isDemo` somem do chat/ranking/perfis; login mostra só Google/e-mail/SMS configurados (em produção e-mail exige RESEND_API_KEY) e, sem nenhum, um aviso no lugar do formulário. Fotos exigem MODERATION_PROVIDER.
- Celular: `overflow-x: clip` + `overscroll-behavior-x: none` em html/body (nada arrasta para o lado, sticky funciona). O eixo vertical fica LIVRE de propósito: puxar a tela no topo atualiza a página (iPhone/Android) — não volte a pôr `overscroll-behavior-y: none`.
- Contas: Google, código (e-mail/SMS com provedor) e e-mail OU celular + senha (`lib/auth/password.ts`, scrypt). Contato de conta com senha fica não verificado; quem provar o contato depois (código ou Google) toma a conta: `claimUnverified` apaga a senha e derruba as sessões. Nunca vincular por e-mail não verificado.
- Base do Brasil (OpenStreetMap): `public/osm/<UF>/<categoria>.json.gz` + `index.json`, gerados por `scripts/build-osm-data.mjs` (Geofabrik + malhas IBGE; refazer 1x/mês, passo a passo no topo do script). `lib/providers/osm-dataset.ts` lê do disco (local) ou da CDN do site (Vercel) com cache em memória; categoria ausente no índice = nenhuma empresa (sem ir à rede). A fonte `osm` usa a base primeiro (ms por cidade), `sweep()` em pedaços de 250, `regionCities()` para a busca geral percorrer só cidades com empresas (maiores primeiro); Overpass ao vivo só de reserva para cidade específica. Busca com fonte rápida roda na hora na action (sem fila). O job trabalha em rodadas (`concurrency`): 1º pedaço de cada cidade em paralelo, UMA consulta `knownMarks` para a rodada, confere em partes pequenas (não as 250 do pedaço) e grava a rodada numa leva (`insertNewLeads` + `saveSweeps`, upsert em SQL). Medir: `scripts/bench-search.mts` (conta temporária; mostra cidades/UF/categorias/repetidos).
- Busca real (OpenStreetMap ao vivo, reserva): consulta pelo código IBGE (`lib/domain/data/municipios-ibge.json`, `node scripts/update-municipios.mjs`), rodízio de servidores Overpass com castigo de 2 min para quem falhar, principais antes das reservas. Job roda cidades em paralelo (`concurrency` da fonte), grava leadIds a cada rodada, retoma de `progress` e para em 230 s; se a 1ª rodada falhar inteira, desiste e explica. Fila: até 4 buscas por instância. Depurar a fonte isolada: `npx tsx --conditions=react-server --env-file=.env scripts/debug-osm.mts barbearia "Belo Horizonte" MG`.
- Custo zero é o padrão: fonte = OpenStreetMap. Google Maps é pago e só liga com opt-in duplo (`DATA_PROVIDER="google"` + `MAPS_API_KEY`, `googleMapsEnabled()` em lib/env.ts); desligado, some da lista, o proxy de fotos não chama o Google e `leadPhotos()` volta vazio. Ligado, cada requisição real reserva vaga no contador do mês (`reserveGoogleRequest`, tabela `ApiUsage`, UPDATE condicional) até `GOOGLE_MAPS_MONTHLY_LIMIT` (900); acabou → `QuotaExhaustedError` e a busca vira OSM (`quotaFallback` nos params). Fotos do Google só com `GOOGLE_MAPS_PHOTOS=true`. Se um dia ligar: não pedir campos Atmosphere (ex.: editorialSummary) — encarecem o SKU.
- Overpass público é instável (504/timeout em horários de pico): cache de 30 dias por cidade×categoria, compartilhado entre usuários, e `cachedProviderCall` devolve a resposta vencida quando a fonte cai (guarda até 90 dias).
- Links de presença: sem Instagram/site a fonte → pesquisa no Google (nome + cidade); Maps sempre (busca no Google Maps). Telefones: `pickPhone` (vários números no campo, celular primeiro) e celular antigo de 8 dígitos ganha o 9.
- Textos de abordagem só afirmam o que o app sabe: nada de "vi no Google" para dado que veio do OpenStreetMap.
- Busca em varredura: `SearchSweep` guarda o cursor por usuário×fonte×categoria×cidade; a próxima busca continua dali e marca "esgotada" quando a fonte acaba (volta após 30 dias, `REVISIT_MS`). Fonte que limita resultados implementa `sweep()` (Google: grade de quadrantes em `lib/providers/grid.ts`, pilha no cursor, viewport 180 dias e quadrante 24 h no `ProviderCache`); sem `sweep()`, a cidade vem inteira (OSM) ou por offset (demo). Busca geral = `regionOrder` (seed por usuário) + posição em `city "*"`. Google filtra lugares de outra cidade (`inCity`).
- Amigos em `lib/social/friends.ts` (recusa silenciosa; bloquear desfaz amizade). Pedido de mensagem = `ConversationMember.inbox` REQUEST: não conta em não lidas, não mostra "visto"; responder ou abrir de propósito aceita. `User.messagesFrom` FRIENDS barra quem não é amigo. Eventos ao vivo `friend` e `inbox`.
- Pix direto: `buildPixCode` (lib/payments/pix.ts, testado contra o exemplo do BCB) + `BankAccount` criptografado (`lib/finance/banks.ts`, tela só vê finais). Confirmar recebimento passa por `applyPaymentUpdate` e vira venda MANUAL não verificada (0 pontos, fora do ranking).
- Arquivos: fotos = `SITE_IMAGE` (moderadas, públicas por id); vídeo/áudio = `FILE_VIDEO`/`FILE_AUDIO`, só o dono por `/api/files/[id]` (nunca por `/api/media`). Envio em partes: `appendPart`/`finishParts` (lib/media/store.ts); entrega com Range: `serveMedia` (lib/media/serve.ts). Cota 300 MB (`assertQuota`).
- Toque: `Button`/`Toggle` crescem só em tela de toque (`pointer-coarse:min-h-*`/`min-w-*`, nunca encolhem); alvo novo pequeno usa o mesmo padrão. Linhas com ações (pessoas, cobranças) empilham no celular (nome em cima, botões embaixo) em vez de tabela larga. Lista longa: primeiros itens + `<details>` "Ver mais".
- Miniaturas: `thumbUrl(src, 160|320|480|800)` (lib/media/thumb.ts) → `/api/media/[id]?w=` (sharp + CDN) ou `w=` do Unsplash; nunca a foto de 1600 px numa grade. Vídeo em grade só carrega perto da tela.
- Prints de auditoria no celular (Playwright): print de página inteira desliga a emulação de toque — use uma aba nova por tela.
- Celular leve: nada de `backdrop-blur` em barra fixa/sticky nem no fundo de Sheet/Dialog (recalcula a cada quadro de rolagem); listas longas com `cv-auto` (+ `[--cv-h:Npx]` = altura estimada). Foco automático e `draggable` só com `pointer: fine` (no toque o teclado cobria a tela e o arrasto disputava a rolagem). Popovers de lista (categorias/cidades): sem autofocus no toque, `collisionPadding` das barras e altura por `--radix-popover-content-available-height`. Alvos de toque crescem com `pointer-coarse:` (Button, Select, Tabs, ícones de presença). Painel do navegador oculto congela rAF: conteúdo do streaming SSR e animações de saída ficam parados (não é bug do app).
- Estúdio (`components/prototypes/studio.tsx` + `components/editor/editor-panel.tsx`): editor em 2 níveis (lista de seções → seção aberta com barra fixa "‹ Seções", ‹ › e "Ver no site"). Computador: painel à esquerda, clique no site abre a seção, abrir pela lista rola o site até ela (`focus` do `DevicePreview`). Celular/tablet: sem gaveta por cima (o teclado do iPhone prendia a tela); barra de baixo "Ver site | Editar", toque no site só seleciona e mostra "Editar ›", site escondido com `<Activity>` enquanto edita. Prévia recebe `useDeferredValue(spec)` e `DevicePreview` é `memo`: digitar não espera o site redesenhar. Celular abre no formato celular sem moldura (`bare`). A barra do app some no estúdio abaixo de lg.
- Espaço de arquivos: mídia fica no Postgres (Neon grátis = 0,5 GB no total). `assertPlatformSpace()` (lib/media/space.ts, teto STORAGE_TOTAL_MB, padrão 350) roda em todo `saveImage`/`saveChatAv`/1ª parte de `appendPart`; cota por conta STORAGE_USER_MB (padrão 60) em Arquivos. Fotos na versão pública exigem MODERATION_PROVIDER (sightengine ou openai); vídeo/áudio não.
- Pontos: `pointsForSale` = 1 ponto a cada R$ 10 (teto 1.000) + bônus de 100 a partir de RANKING_MIN_SALE_CENTS; abaixo do mínimo vale ao menos 1 ponto (toda venda paga pelo link aparece no ranking). Níveis (`salesStats`) só contam vendas a partir do mínimo; o perfil mostra tudo (`verifiedTotals`). Ultrapassagens: `announceOvertakes` (lib/ranking/overtakes.ts) publica evento `rank` (up/down) e o `PresenceHeartbeat` mostra o aviso em qualquer tela; feed "Acabou de acontecer" na Comunidade (`cachedRecentSales`).
- Chat: "Apagar para mim" = `Message.hiddenFor` (qualquer participante; `listMessages` filtra); recebido tem menu com Apagar para mim e Bloquear. Vídeo: `readVideo` nunca bloqueia (capa neutra se o navegador não tirar quadro; iPhone só carrega com metadata + seek); acima de 16 MB `compressVideo` (canvas + MediaRecorder, ~1 Mbit/s) antes de subir.
- Janelas (`DialogContent`): toque fora NÃO fecha no celular (teclado); `persistent` faz o mesmo no computador (cobrança). Conteúdo com max-h e rolagem. A cobrança reabre com o que já tinha preenchido.
- Excluir conta: Configurações e Perfil → `deleteAccount` (cascata em tudo, invalida placar, recarga completa para `/login?conta=excluida`).
- Auditoria no navegador: o app proíbe iframe (`frame-ancestors none`), então sondas que usam iframe precisam navegar pelo `window.next.router`. Itens com `cv-auto` fora da tela dão `innerText` vazio — "sem nome" nesses casos é falso positivo (confira com textContent/label).
